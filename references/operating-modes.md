# Proportional DRGB operating modes

Choose the lowest mode that completely covers the action's real consequence,
not its apparent implementation size. If a task combines modes, run the
strictest mode for the consequential part.

## Light — bounded reversible work

Use for read-only discovery and small, reversible, named-scope changes such as
a single dashboard, documentation, or local-code correction.

Required: exact scope; expected outcome and falsifier; backup or rollback
locator before deployed-state changes; independent verification; concise claim
and completion event.

Not allowed: service/deployment changes, cross-host/account work, credentials,
money, or external effects.

## Standard — operational change

Use for service or deployment work, multi-agent or cross-system changes, and
larger reversible repairs.

Required: all Light evidence; current authoritative preflight; deterministic
policy verdict; scoped rollback; independent verifier; coordination claim,
completion evidence, and handoff.

The owning system remains controlling. A Standard profile cannot bypass an
authenticated or domain-specific gate.

## Full — consequential action

Use for trading, money or custody, credentials, identity, outbound messages,
purchases, destructive work, or any irreversible outcome.

Required: all Standard evidence; fresh authenticated source-of-truth evidence;
the named owning deterministic executor and its exact gate; required operator
or tier-A approval; and post-action independent reconciliation plus a
compensation or rollback path where meaningful.

Models, agents, memories, graphs, and coordination journals provide evidence;
none grants authority. Missing, stale, ambiguous, or conflicting evidence
blocks the consequential path.
